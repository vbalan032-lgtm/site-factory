# Site Factory project context

Read `.site-factory/project.json` first. It defines the project identity and exact source-of-truth, lifecycle, and graph paths. Read the configured master context and only the supporting files relevant to the current task.

The immutable brand core, proof discipline, public Russian-language requirement, logo rules, and approved project positioning outrank optional visual taste. Layout, typography, composition, motion, and component patterns are evolvable only through an approved `CREATIVE_BLUEPRINT.md` that records `benefit`, `risk`, and `brand bridge`.

Before v3 page work, use the project `context-pack-loader` stdout JSON as the graph-first and only default context entry for Webpage, Loop, SEO, GEO, and shared-checker work. The pack satisfies baseline project loading; read primary sources only through `exact_source_triggers`, changed fingerprints/conflicts, or an explicitly requested cross-cutting audit. Website Foundation and business-document owners retain direct primary-source access. Never create a tracked `CONTEXT_PACK.md`. The global `context-loader` is compatibility/focused legacy only and cannot bypass Graphify or exact-slice safety.

For design routing follow `docs/system/DESIGN_SKILL_ROUTING.md`. Stage 2 may use optional reference/live-route inspection. Stage 5 may use an advisory smoke when a runnable page exists. Stage 6 owns full-page desktop/mobile, interaction, accessibility-tree, and SSR/SEO evidence. Stage 7 may run staging smoke only when staging work is authorized. Do not run routine Playwright for Stage 1, Stage 3, ordinary context reads, or state-only updates.

Use Superpowers only for its exact triggers: `superpowers:brainstorming` for unresolved creative/behavior design, `superpowers:writing-plans` for multi-step implementation planning, `superpowers:test-driven-development` for features and fixes, `superpowers:systematic-debugging` for unexpected failures, `superpowers:requesting-code-review` for substantial completed work, and `superpowers:verification-before-completion` before completion claims. The full workflow is not triggered by ordinary copy, context reads, or state-only updates.

Public website UI and copy use Russian Cyrillic except configured brand and technical terms. Check claims against the configured claims source. Never invent facts, proof, credentials, or approvals.

Remote Git, meaningful commits, staging, merge, release, and production actions require explicit human approval. Never store tokens, OAuth data, private keys, or passwords in the repository.
